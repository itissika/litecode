# WP-195 调研 brief — bash 系列是否进 Code 模式

**分支：** `feat/tool-contract-ptc`（只读调研为主；不要求改码）  
**口径（Andy）：** 分析 bash 系列能否进入 code 模式；挑战、风险、收益；**bash 工具本身设计是否要调整/修改**。  
**产物：** 总分结构、易于阅读的调研报告 md（细节附录留档）；GM 审读后聊天发给 Andy，再封包。

## 要答清的问题
1. **能否 / 该不该** 把 bash（及同族：shell / 终端类若有多个）做成 Code 面工具（经 `tools.*` 在 `run_code` 内编排）？
2. **挑战：** 与现有 Direct 面 bash 的权限/审批/超时/流式输出/交互/工作目录/并发模型如何对齐；与五文件工具 + run_code 预算/封口/unsettled 如何共存。
3. **风险：** agent 误用、副作用不可见、绕过文件账本、权限面扩大、错误形态是否仍易理解。
4. **收益：** 编排密度、少 round-trip、与 read/edit/write 同程序内组合等。
5. **工具设计是否要改：** 若进 Code，参数/返回契约、流式/分块、审批挂起、失败码是否要相对今日 Direct bash 重新设计；若不进，Direct bash 是否仍建议小改以配合 code 生态。

## 非范围
- 本包不实现、不合 main；最多附「可选后续包」建议。
- 少陷纯工程实现细节与人类 UI；站在 **agent 易理解/易用**。

1. `artifacts/WP-195/report.md`：总分 + 大结论散文 + 附录证据。
2. 明确给出倾向结论（进 / 不进 / 有条件进）及对「bash 设计要不要改」的直接回答。
