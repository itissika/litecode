# WP-204 分析 — 工具/管线改造后提示词文本面查漏补缺

**分支：** `feat/tool-contract-ptc`（只读审阅；不合 main）  
**口径：** Andy 2026-10-22。大量工具与管线改造后，审 agent **可见**提示词文本面。  
**产物：** `.litecode/ops/artifacts/WP-204/review.md`（总分可读 + 附录证据）。本包**不要求改码**；结论可建议后续包。

## 审什么（agent 可见面）

覆盖系统固定提示词、Code/PRELUDE/SDK 教法、各工具 live description、以及任何随绑定注入的卡面文案——凡是模型回合里能读到的文本。

对照轴（每条要有结论 + 证据路径/摘录）：

1. **冗余**：同义反复、过期方言、与已硬清实现重复的说明（对照 WP-196…203 后的活跃面）。  
2. **精准**：契约/坐标/失败形态/软硬失败边界是否与现行实现一致；有无过时 camelCase、单 `lsp`+action、`text` 定位、Direct bash 等。  
3. **自相矛盾**：系统层 vs 工具层、PRELUDE vs description、工具 A vs 工具 B 说法冲突。  
4. **域隔离（可拔插）**：基于 Settings 可拔插——某工具的用法/要求是否渗入系统固定提示词或其他工具文案；未绑定工具是否仍被系统面点名强推。  
5. **系统固定提示词稳**：固定层只谈跨工具不变量与工作流，**不**渗入单独工具的用法与要求。

## 非目标

- 本包不改码、不刷 fixture（除非审阅发现 blocker 需另开实现包）。  
- 不合 main；不改 `web/` 人类 UX。  
- 不重做 WP-193 全架构总评；本包聚焦**提示词文本**查漏补缺。

## 报告形态

- 前半：一句话总评 → 按上列五轴各一段可读结论（严重度从大到小）。  
- 后半：附录（路径、摘录、建议后续包草案）。  
- 路径：`review.md`
