### ③ -32801 ContentModified 重试（conn.rs:23-45 白名单+退避，:504-533 request_retry_modified）—— 两家都不重试，建议调整（须批）
- vscode-languageclient：`handleFailedRequest` 遇 ContentModified：语义 token 类与 *resolve 类抛 CancellationError，其余请求「静默返回 defaultValue（空结果）」，不重试，不记错误日志。
  https://github.com/microsoft/vscode-languageserver-node/blob/d91883defb99bdbbc2419450f6eba334b981dfb0/client/src/common/client.ts#L2291-L2331
  并在 initialize 声明 `general.staleRequestSupport = { cancel: true, retryOnContentModified: [semanticTokens 三个方法] }`（client.ts:2140-2144）——即告知 server「只有这几个方法客户端会自行重发」。
  https://github.com/microsoft/vscode-languageserver-node/blob/d91883defb99bdbbc2419450f6eba334b981dfb0/client/src/common/client.ts#L2140-L2144
- Zed：`ResponseError::is_request_denied()` 把 ServerCancelled 与 ContentModified 视为「请求被拒」（lsp.rs:393-396），lsp_store 据此不记日志（lsp_store.rs:4778；测试 :17489），不重试；只有 ServerCancelled 带 retrigger 时才重发（should_retrigger）。
  https://github.com/zed-industries/zed/blob/26363aabdb31a0c016728634202e1ad5067033aa/crates/lsp/src/lsp.rs#L393-L400
  https://github.com/zed-industries/zed/blob/26363aabdb31a0c016728634202e1ad5067033aa/crates/project/src/lsp_store.rs#L4778
- 结论：ISSUE-044 的「hover 等只读请求 3 次退避重试」是自造机制，与两家不一致。差异的根源：编辑器下次按键会自然重发，agent 工具调用不会，所以「静默返回空」对 agent 会造成假阴性（与引擎规则「宁缺勿假」不冲突，但会让 agent 以为无结果）。
- 建议改法（须批，二选一交中层/GM，涉产品行为可能需 Andy 定）：
  A（照抄 VS Code）：去掉 request_retry_modified 与 RETRYABLE_READ_METHODS；-32801 时返回空结果，并在工具输出里注明「server 正在更新（ContentModified），结果可能不全，可稍后重试」；initialize 声明 staleRequestSupport{cancel:true, retryOnContentModified:[]}。测试：mock 返回 -32801 → 工具输出空+提示；rust_analyzer_smoke 需改为对提示容忍或在就绪后断言（会变动 :1488 目标）。
  B（保留重试，但挂到标准机制上）：保留现有有限重试，同时在 initialize 声明 staleRequestSupport.retryOnContentModified 为白名单方法，使重试成为 LSP 规范声明的客户端行为而非私有约定。改动小、smoke 保持绿。
  我的推荐：B（规范内、语言通用、对 agent 更可靠）；若 Andy 坚持逐字照抄则 A。
