# WP-057 检索引擎产品口径落地

## Goal（Andy 2026-10-12 终版锁定）
按锁定口径改 code_search / session_search / 引擎生命周期与工具面，使人/agent 能用、不傻等、不假可用。

## 锁定口径（施工唯一依据）
1. **「在暖」一个桶**：凡起来了但还不能搜的（拉进程、不兼容重建中……）都算 Warming。
2. **Warming ⇒ 搜不了，也看不见工具**（禁止「看得见、点了才难用」）。
3. **不在暖 ⇒ 总能搜**：索引再瘦也是能搜；没命中=搜不到，不是「还不能用」。
4. **重建例外**：仅首次 / 不兼容。**不做「脏到不能用 → 全量重建」**——能刷就刷。
5. **刷新**：静默后台，不挡搜；结果机械比对，宁可不给也不给假的。
6. **工具结果视图开头固定同步百分比**（agent 可判断索引齐不齐）。
7. **暂时不默认开** retrieval（开销大）；关着时工具本就不可见——与「Warming 不可见」一致，不靠默认开来解决可用性。

## 废止的旧说法
- 「空结果才谈库旧」作为主叙事 → 改为：没命中就说没有；可附索引提示，但不代替「没有」。
- DirtyTooLarge / 「脏到不能用」触发重建 → 废止。
- 暖机同步睡满与 timeout 对齐 → 废止（Warming 不应进入可调用面）。
