# WP-016 冻结包 · 检索引擎产品行为

## Andy 口径（讨论收敛）
- 「在暖」= 引擎有没有拉起来，不是整库重建
- 首次建起后常态只刷增量；不应有常用全量重建路径
- 引擎起来就能搜；刷不挡首搜
- 结果机械比对真相：有命中且对就给；一条都没有再谈库旧/没建好
- 核心痛点：慢、空刷重试、用不了 —— 优先拆工具同步傻等与催重试环

## 状态
**blocked / 冻结**：核对完写入本节证据后，bot 无需再干；等一批提交后再开落地包。

## 核对结果（IDE 只读 · 2026-10-12）

**结论：** code 与 session **都有**全量重建路径；但首次建起且索引兼容后，设计上应只走增量 Update。再全量的理由：`FirstDesired` / `Incompatible` / `DirtyTooLarge`。

- 共用：`IndexWork::{None,Update,Rebuild}`（`index_status.rs`）
- code：全量 `build_full_index` / `rebuild_index_in_runtime`；增量 `refresh_index_incremental`
- session：`session_work_*` 同样 Rebuild/Update
- 合并：`engine_index_work = merge(code, session)`

与 Andy 口径对齐点：常态应是「起来 + 刷」；全量重建应是例外（首次/不兼容/脏爆），不应是常驻「还在暖=重建」。
