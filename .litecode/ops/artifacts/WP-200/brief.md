# WP-200 实现 — run_code 管线硬清冗余分层

**分支：** `feat/tool-contract-ptc`  
**口径：** Andy+GM 定稿。不符合本设计的**全部杀掉**；可参考 pi codemode 对 agent 友好的宽容处理，**禁止**再堆冗余信息。

## 方向（一句话）

`run_code` 是单次聚合管线，不是调试观测台：过程**失败可见、成功静默**；结果按窗尽量保留；工具自己返回的信息还给工具；`run_code` 只保留必须不变量。

## 模型视图（唯一目标形态）

1. **Head（不变量）**
   - 跑不起来：精准报错——哪一行、什么错（可有足够定位，不堆栈噪音）。
   - 跑起来了：成功了多少、失败了多少、耗时多少（一两行够用）。
2. **Logs（自愿）**：脚本自己写的过程日志；没有就不出现。成功工具调用**不**自动占位。
3. **Result**：脚本返回值按现有窗口策略尽量保留；失败时**尽量保已有 result/partial output**（学 pi：失败不空白抹掉）。

**禁止**再作为默认模型面出现的：独立 failure 大段、diagnostics 层、全量成功+失败 ledger、与工具 ok+message 重复的错误复述、其它「兼容观测」冗余分层。内部诊断若需要，可留在测试/人看通道，**不进**默认 agent 视图。

## 边界原则（学 pi）

- 嵌套工具结果是脚本数据，默认不进主视图；模型要过程自己 log/return。
- 工具契约错误归工具自己的 `{ok,message}`（或等价）；不要在 `run_code` 再包一层同义复述。
- 宽容：失败保留已产出；`undefined` 等按既有/pi 友好规则处理，勿借机加方言字段。
- 硬清：旧分层符号与渲染路径能删就删，不要双轨兼容。

## 验收

1. 默认模型视图符合上三块；冗余分层清零（代码与测例可证）。
2. 跑不起来：行+错清晰；跑起来：成功数/失败数/耗时；成功静默、失败可见。
3. 结果按窗尽量保；失败不空抹。
4. cargo 绿；`artifacts/WP-200` 齐；push 实验分支；**未合 main**。

## 非目标

- 不改 shell/edit/grep 等已定契约（除非为删 run_code 冗余所必需的最小触碰）。
- 不合 main。
