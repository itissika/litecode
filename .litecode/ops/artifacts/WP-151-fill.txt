# WP-151 前端瘦身调研（只读，不改代码）

目标：盘点 web 和 desktop 的可瘦身项，交付 `.litecode/ops/artifacts/WP-151-frontend-audit.md`，作为后续瘦身包和多语言包的依据。整包只读：不改产品代码，不加依赖，不 commit。knip 一类工具只能临时用 npx 跑或装在 /tmp，不写进 package.json 和锁文件。

## 交付内容（五节，每条都附建议和风险；需要产品判断的标「待 Andy 定」；后端报错原样保留，不在统计和删改范围内）
1. 死代码：没被用到的文件、组件、导出和依赖。先用 knip 扫（web 再加 ts-prune，或用 tsc 的未用检查交叉验证），再逐条人工确认，附路径和证据（rg 无引用、只被测试引用、动态 import 等）。分成「确认可删」「疑似，需复核」两类。
2. 可合并的重复组件：给出成组的路径、差异点、建议的合并目标，以及影响面。
3. 多余提示文案：按面板列（设置各节、引擎、Agents、Providers、聊天区、工具视图、桌面壳等），每条标「可删 / 可合并 / 可缩短」，附原文和建议文。
4. 功能介绍文档大纲：只收有界面、有交互的功能，内部特性不写。按左侧栏底部常驻问号按钮打开的弹框（和设置弹框同款）来组织：分节标题、每节一句要点、对应入口。
5. 写死在界面里的文案统计：按目录和面板列条数与字符量，区分普通 UI 文案、提示和 tooltip、错误提示（不含后端原样透传的报错），并说明统计口径和脚本，给多语言包估量用。

## 拆分（kind=split，三个子包按顺序，不打乱在途任务）
- 子包 A（owner frontend / 前端-web）：web 部分的五节原始调研，产物写到 `WP-151-web-audit.md`。
- 子包 B（owner frontend_desktop / 前端-desktop）：desktop 和 scripts 部分的五节调研（主要是第 1、2、5 节；第 3、4 节有界面的才写），产物写到 `WP-151-desktop-audit.md`。只做静态分析，不构建，不在真机运行。
- 两个子包可以并行，因为目录不重叠，都只读，也不占同一文件。
- 前端中层：交叉抽查证据（死代码每类抽样 rg 复核），然后合成总产物 `WP-151-frontend-audit.md`。总产物里给出跨端的重复组件、「待 Andy 定」汇总，以及按风险排好的后续瘦身包建议顺序。
