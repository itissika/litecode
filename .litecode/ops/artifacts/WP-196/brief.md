# WP-196 实现 brief — bash 家族最低风险切口进 Code（含防退化）

**分支：** `feat/tool-contract-ptc`（实验分支；未要求合 main，交付后由 GM 决定）  
**前提：** WP-195 调研证据仍有效；**Andy 纠正产品结论**——最终要进 Code，不能因难度/风险得出「不进」。Direct 下模型大量退化到只用 bash，是必须解的问题。  
**口径：** 开**实现包**；选**最低风险切口**先把 bash 家族能力送进 Code；验收必须含**防模型退化**。

## 方向（GM，不绑实现细节）

1. **目标态：** Agent 能在 `run_code` 内用结构化 shell/命令能力与文件工具同程序编排（改完就测少往返），不再被逼退到 Direct-only bash。
2. **切口原则（最低风险）：**
   - 禁止「只改 `surface()`」；必须满足 WP-195 Runtime dig §7 门槛中与本切口相关的子集（成功 `data`、等待不堵预算、程序结束语义清晰、会改文件则有 `effects`、长日志走路径+分页、同面一致性）。
   - 优先选调研里风险更低的切口（例如新前台可取消结构化执行工具，Direct 作业三件套可暂留）；若选「现有三件套整体 code 化」，方案里必须写清为何仍是最低风险、以及如何一次满足门槛。
   - Direct 长作业协议可保留，但**不得**继续当「改文件/跑测」的默认逃逸口。
3. **防退化（产品硬要求）：** 改完后模型不应再系统性退化到「凡事 Direct bash」；教学/描述/投影应引导 Code 内编排。

## 非范围

- 不顺手改无关权限 floor 缝、人类 UI、无关 PTC 文案大扫。
- 不合 main，除非 GM 另批。

## 验收（done_when）

1. 方案经 GM 批准后落地：Code 面可调用的 bash/命令能力可用；成功返回稳定 `data`（至少能编排：状态、退出码、有界输出或 `output_file`）。
2. 与 `run_code` 预算共存：等待不饿死预算 watcher；取消/超时语义在产物里写清，且单测或等价证明覆盖关键路径。
3. **防退化：** 交付说明 + 必要描述/SDK/教学改动，证明典型「改文件→跑命令→看退出码再改」可在 Code 内完成；Direct bash 不再是该路径的默认/唯一通道；附最小对比或场景说明（agent 视角）。
4. 测试：相关 `cargo test`（至少覆盖新契约/准入/嵌套关键路径）绿；产物在 `artifacts/WP-196/`（acceptance + 方案/diff 摘要）。
5. 分支推到 `feat/tool-contract-ptc`（或约定实验分支）；未擅自合 main。
