# 发版

只有重要变更才公开发版：严重缺陷、重大特性、大量体验优化。用户按 Release 取包，不以 main 当已发版。

## 顺序

1. 升版本号：`Cargo.toml` 为准，同步 `desktop/package.json` 等。
2. 合并发版描述：整理 `CHANGELOG.md` 中该版本的条目（见下）。
3. 本地 `package_local.ps1` 验证通过。
4. 打 tag `v<version>`，Publish GitHub Release（触发 `windows-signed-release`）。
5. CI 只在 Release 正文末尾追加构件说明，不覆盖已有描述。

tag 必须是 `v<version>`，CI 按这个找构件。

## 发版描述（`CHANGELOG.md` + Release 正文）

- **时机**：最终决定触发云端发布时做一次合并更新；升版本号时只记一笔，不写成「最后一次提交」。
- **范围**：上一已发布 tag 至今、对该版本用户可见的全部变更。
- **板块**：固定，最多三个——新特性 / 重大改进 / 其他。
- **写什么**：只讲对用户有收益的改动；讲不出收益的不写。不写内部重构、命名、测试修补。
- **怎么写**：一句大白话，不许有术语，只讲用户能拿到什么。
- **禁止**：元信息（「累计 N 个提交」）、文件名堆砌、上一版已写过的修复、把打包细节冒充整版变更。
- **Release 正文**：以 CHANGELOG 对应节为准；CI 只 append。

## 不做

- 为 CI、文档、内部重构发版。
- 未升版本号就构建发布；擅自改版本号、打 tag、Publish、force 移动已有 tag。
