`run_code` executes one async JavaScript function body with top-level `await` and `return`. Orchestrate multi-step work in a single call instead of one call per turn: run independent calls concurrently with `Promise.all`, chain dependent steps with `await`, branch or nest on intermediate results, and use loops to batch or filter work. You MUST end with `return` for the data or tool results you need—return result objects directly (single result, `Promise.all` array, or summary object) for full output and metadata, or return filtered/sliced summaries; the host automatically formats returned objects, tables, and multiline strings without JSON-escaping.

Call tools as `tools.<name>(args)` (or `tools.<suite>.<member>(args)` for custom suites). A no-argument tool takes no argument; every other tool takes one object matching its declared input schema. Each call returns a promise that resolves to its declared data or rejects with an ordinary JavaScript `Error`; `try`/`catch` and `Promise.allSettled` handle rejections, and a rejected tool error carries `code`, `message`, and optional `details`. For strings containing backslashes or quotes (such as regex edits), use `String.raw` or template literals — but avoid `String.raw` or bare template literals if the embedded text itself contains backticks (`` ` ``) or `${...}` (e.g. Python docstrings, Markdown, or shell scripts), since `` ` `` cannot be backslash-escaped in `String.raw` and `${...}` is still evaluated; use regular quoted strings or concatenation instead. The declarations below are the source of truth for tool paths, argument shapes, and result fields.

`fs` is a synchronous, read-only, workspace-relative probe (`ls`/`stat` throw `Error` on missing or out-of-workspace paths). `libs` are pure-JS helpers. Both are declared below. No direct network, process, module access, or timers (`setTimeout`/`setInterval`) exist; side effects and external IO go through the bound tools.

Unknown tool bindings, output-contract violations, cancellation, the 600000 ms active JS execution cap (paused while tool calls run, subject to a 1800000 ms hard wall-clock cap per `run_code` call), and hard limits stop the cell and cannot be caught. Non-finite numbers in a result become `null` with a warning.

When any output exceeds the view budget, it is cut to a head+tail preview with `… <N> bytes total; full output: <path>`. Every path under `.litecode/run/` holds the complete unclipped output—inspect that path with bounded reads or searches instead of re-running work.
