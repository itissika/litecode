Replace text in one file. The result is `data.file`, `data.blocks`, `data.applied`, and `data.failed`. `data.file` is the identity after the successful blocks are written (`path`, `hash`, `bytes`, and `abs` outside the workspace). Each block is `index`, `status` (`applied` or `failed`), `ranges` (`start_line`, `end_line`), and `reason` (`code`, `message`, optional `details`) when it failed. Optional `expected_hash` is the sha256 from `read` `data.file.hash`. Omit it to skip the check. A mismatch returns `error.code` `"stale"` with `details.current_hash` and does not write. All blocks match the file before any of them apply. Full success is `status: "ok"`. Some blocks applied and some failed is `status: "partial"` with diagnostic `edit_block_failed` (`details.index`, `details.reason`, and `details.ranges`). No block applied is `status: "error"` with `error.code` `"edit_failed"` and `error.details.blocks`; the file is not modified.

Multiple files means multiple calls, one path each. Pass `path` and a non-empty `edits` array; each item is `old_string`, `new_string`, and optional `replace_all` (default false). Empty `new_string` deletes `old_string`. Matching is exact. CRLF and LF compare equal, and a leading UTF-8 BOM is preserved. `replace_all` replaces every exact occurrence. A block that matches more than once without `replace_all` fails with `multiple_matches`.
