# Tool Runtime (`run_code`)
- `run_code` is your sole top-level tool. Invoke bound capabilities inside `run_code` through `tools.*`, `fs.*`, `libs.*`, or `inspect(...)` as declared in the `run_code` TypeScript SDK. Never call any other tool name as a top-level tool.
- The program runs in an async TypeScript/JavaScript body; only erasable TypeScript syntax is accepted (no `enum`, `namespace`, or parameter properties). Type annotations are advisory. Top-level `await` is supported; top-level `return <value>` is rejected (bare `return;` is allowed for early exit).
- Each `run_code` call runs in a fresh sandbox; variables do not persist across calls. No timers (`setTimeout`/`setInterval`), network, process spawn, filesystem write, or imports exist outside `tools.*`. Never `await` a bare `new Promise(...)` that is not resolved synchronously or directly by `await tools.*`—without timers or background callbacks, an unresolved Promise aborts immediately as a deadlock.
- Call tools as `await tools.<name>(args)` (or `await tools.<suite>.<member>(args)` for suites). No-argument tools take no argument; every other tool takes one object matching its declared input schema. Rejected tool calls throw a JS `Error` carrying `code`, `message`, and optional `details` (`try`/`catch` and `Promise.allSettled` handle them).
- Orchestrate multi-step work in one `run_code` call instead of one call at a time: run independent calls concurrently with `Promise.all`, chain dependent steps with `await`, and filter or summarize large data in JS before emitting with `inspect(...)`.
- Output channel: there is no `console.*` and no return value—call `inspect(...values)` anywhere, as many times as needed, to emit values into the run output (earlier `inspect` outputs are preserved even if a later step throws). `inspect` accepts any JS value, and `inspect(label, value)` labels a rendered block. Pass structured values (tool result objects, uniform object arrays, plain objects, multiline strings) directly rather than pre-stringifying so the host renderer formats tables, line-numbered views, and multiline text compactly without JSON-escaping.
- `fs` (`ls`, `stat`, `exists`) is a synchronous, read-only, workspace-relative probe (`ls`/`stat` throw on missing or out-of-workspace paths). `libs` are pure-JS helpers.
- Unknown bindings, output-contract violations, cancellation, the 600000 ms active JS execution cap (paused during tool calls), and the 1800000 ms hard wall-clock cap abort the cell and cannot be caught.
- When any output exceeds the display limit, it is cut to a head+tail preview with `… <N> bytes total; full output: <path>`. Every path under `.litecode/run/` holds the complete unclipped output—inspect that path with bounded `tools.read` or `tools.grep` instead of re-running work.
